## 1. Введение
Цель — получить воспроизводимый образ Linux и подтвердить выполнение пользовательского кода на Discovery. Первый этап проверяет сборочную цепочку и доступ к MCU. Пункты с пометкой «предложение» требуют решения владельца до реализации.

[R] — восстановлено по коду, [N] — новое требование, [U] — уточнение существующего поведения. Исходной прошивки проекта нет. По правилам документа разделы 3–4 — нормативные. Номера пунктов и TC сохраняются при пересмотре.

## 2. Стенд и границы
SWD — двухпроводный интерфейс отладки. ST-LINK соединяет ПК с MCU. Его USB-идентификатор подтверждает присутствие отладчика, тип цели проверяют отдельным чтением. Для ядра без MMU потребуется согласовать размещение загрузчика, ядра, DTB (описания оборудования) и корневой ФС. Доступную SDRAM нужно испытать до загрузки ядра.

## 3. Функциональные требования
3.1.1. [N] Из чистой локальной копии без платы и сети сборка ДОЛЖНА дать ELF для Cortex-M4 с векторами и кодом целиком внутри выделенного окна SRAM. Проверка сопоставляет начальные SP и PC с границей стека и точкой входа ELF.

3.1.2. [N] Проверка подключения ДОЛЖНА считать идентификатор семейства через SWD без записи Flash. В отчёте фиксируются инструмент, режим, частота, адрес и результат чтения.

3.1.3. [N] Предложение. Пробная программа ДОЛЖНА после запуска из SRAM записать значение 0x429 в символ probe_result и дойти до probe_done. Проверка использует символы собранного ELF.

3.1.4. [N] Предложение. После холодного старта система ДОЛЖНА вывести версию ядра и выполнить в пользовательской оболочке команду uname -r. Сохранённый вывод должен совпасть с kernelrelease проверяемой сборки.

3.1.5. [N] При первом запуске ядра через SWD система ДОЛЖНА передать по USART1 строку Linux version с версией проверяемой сборки. Windows сохраняет её в журнале COM21, открытом до старта ядра. (р.1.1)

3.1.6. [N] Ядро ДОЛЖНО запустить /init из встроенного initramfs. После проверки getpid() == 1 процесс передаёт контрольное сообщение через стандартный вывод на COM21. (р.1.2)

3.1.7. [N] Оболочка, запущенная на плате, ДОЛЖНА принять команду uname -r, введённую с Windows через COM21, вернуть версию работающего ядра и снова показать приглашение. (р.1.3)

3.1.8. [N] Linux 6.14.5 должен поднять eth0 на LAN8720 через RMII и ответить на ICMP Echo Request со стендового ПК. Холодный старт проверяется отдельно по TC-04. (р.1.4)

3.1.9. [N] Плата должна принимать SSH с ПК по ключу и обеспечивать передачу файла 16 КиБ в /tmp и обратно с совпадением SHA-256. (р.1.5)

3.1.10. [N] Загрузчик, DTB и сжатое ядро с initramfs должны помещаться в 2 МиБ внутренней Flash и запускать Linux после распаковки в SDRAM. При холодном старте загрузчик должен самостоятельно установить HCLK=168 МГц и SDCLK=84 МГц. [U] (р.1.6)

3.1.11. [U] После холодного старта initramfs должен предоставлять компактный BusyBox и /bin/tcc. Через SSH компилятор должен собрать в /tmp программу на C с вызовом puts и выполнить её на плате. (р.1.7)

3.1.12. [U] Демонстрационный образ должен принимать SSH по паролю user для учётной записи user (UID/GID 1000), отклонять неверный пароль и вход root. SCP и TCC должны работать в /tmp. Индивидуальный ключ узла создаётся при первом старте и сохраняется при выключении питания. (р.1.8)

3.1.13. [U] Компактный BusyBox должен предоставлять интерактивный top для просмотра CPU и памяти через SSH. Сумма отображений оболочки в начале сеанса не превышает 128 КиБ. (р.1.9)

3.1.14. [U] Плата должна вывести на LCD читаемую строку знаками 5×8, сохранить PG11 в AF11 за Ethernet и отвечать на ping со стендового ПК во время записи изображения. (р.1.10)

3.1.15. [U] Устройство /dev/fb0 должно хранить 40×40 символов в 1600 байтах SDRAM. От имени user программа TCC должна выводить через lcd-text строку на SPI5 без потери работоспособности Ethernet. (р.1.11)

3.1.16. [U] Полная заливка ILI9341 должна передаваться блоками по восемь строк при прежнем делителе SPI5. Проверка должна сравнивать время, TX DMA IRQ и ответы Ethernet с прежней реализацией. (р.1.12)

3.1.17. [U] На плате сравнить последовательную и перекрывающуюся подготовку строк. Показать uptime с секундами в центрированной рамке почти на всю ширину экрана. (р.1.13)

## 4. Верификация
| TC | Условия и действия | Признак успеха |
| --- | --- | --- |
| TC-01 | В чистой копии выполнить make check без USB | Код 0, проверены таблица векторов, адреса и размер ELF |
| TC-02 | Подключить ST-LINK, прочесть DBGMCU_IDCODE по процедуре BUILD | Биты 11…0 равны 0x419 |
| TC-03 | На согласованной плате остановить MCU, загрузить ELF в SRAM, обнулить probe_result, установить SP и PC по векторам и продолжить до probe_done | Отладчик остановился на символе, прочитано 0x429 |
| TC-04 | Подключить согласованную консоль, снять питание и запустить утверждённый образ, записать сеанс | Версии ядра при старте и из оболочки соответствуют сборке |
| TC-05 | Открыть COM21 (115200 8N1), передать управление точке входа Linux с DTB, сохранить полученные байты | В журнале есть Linux version и значение kernelrelease собранного ядра |
| TC-06 | Загрузить ядро с минимальным /init, открыть COM21 до старта и сохранить последовательность сообщений | После сообщения таймера и запуска /init принят маркер F429-DISCO /init: PID=1 userspace reached |
| TC-07 | Дождаться приглашения, передать uname -r с Windows по UART, записать TX и RX | Получена отдельная строка, совпадающая с kernelrelease, затем новое приглашение |
| TC-08 | Зафиксировать в COM21 привязку PHY и eth0, отправить ICMP Echo Request с ПК | Получен Echo Reply с адреса платы с совпадающими идентификатором, номером и данными запроса |
| TC-09 | Подключиться по SSH, выполнить uname -r, передать файл в /tmp и обратно | Вход по ключу, версия 6.14.5 и три одинаковые суммы SHA-256 |
| TC-10 | Проверить границы BIN, прошить и запустить из Flash | BIN ≤ 2097152 байт, распаковка и CRC успешны, RCC и FMC подтверждают штатный профиль 168/84 МГц, Linux загружается |
| TC-11 | После TC-04 и TC-09 проверить суммы /bin/busybox и /bin/tcc, скомпилировать Hello World в /tmp и запустить через SSH | Получены ровно 14 байт Hello, World! с LF и статус 0 |
| TC-12 | Два запуска одной платы, сверка публичного ключа с COM21, независимые попытки входа, UID/GID, проверка доступа, SCP и TCC | Ключ одинаков; root и неверный пароль отклонены; UID/GID 1000, три одинаковых SHA-256 и Hello World |
| TC-13 | В SSH PTY запустить hush из проверяемого бинарника, измерить /proc/$$/maps, выполнить top -d 2, дождаться трёх кадров и нажать q | Оболочка ≤128 КиБ, видны память, общий CPU и %CPU процессов, приглашение возвращается |
| TC-14 | На MB1075 B-01 вывести LINUX 5X8 по последовательному интерфейсу ILI9341, параллельно отправлять ping, проверить режим PG11 | Оператор прочёл строку, получены ответы ICMP и PG11 остался AF11 |
| TC-15 | Скомпилировать C-пример на плате, передать stdout в lcd-text, измерить заливку, DMA IRQ, содержимое fb0 и ping | Надпись видна, прочитаны 1600 ожидаемых байт, счётчик TX DMA вырос, PG11 AF11 и ping проходит |
| TC-16 | Для каждого образа выполнить пять одинаковых заливок без текста, снять время ioctl, DMA IRQ, делитель и ping | При том же делителе получены 40 вместо 320 IRQ за заливку, меньшая медиана времени, ответы ping и корректное чтение текста |
| TC-17 | Передавать заливку, 40 знаков и 40 разных строк, сверять время, DMA IRQ и прочитанные ячейки; запустить uptime | Получено сравнение, рамка с полями видна, секунды меняются |
