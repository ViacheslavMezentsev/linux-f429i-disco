# Сборка и проверка

## Чистая локальная копия
В WSL нужны Git, GNU Make, Python 3.8+ и GNU Arm Embedded (arm-none-eabi-gcc и binutils в PATH). Проверено с GCC 10.2.1. При необходимости пакет Ubuntu называется gcc-arm-none-eabi.

```sh
src=~/github/ViacheslavMezentsev/linux-f429i-disco
dst=$(mktemp -d)
git clone --no-local -b codex/bringup "$src" "$dst/repo"
cd "$dst/repo"
make check
arm-none-eabi-readelf -hl out/probe.elf
git status --short
```
Ожидаются ноль замечаний по ТЗ, TC-01 PASS и пустой status. ELF связан для первых 4 КиБ внутренней SRAM. Два начальных слова задают стек и вход в Thumb-код, который маскирует прерывания, записывает маркер и остаётся в цикле. Образ предназначен для запуска отладчиком. Его сборка не требует Linux toolchain для userspace.

## Протокол подключения, 04.11.2026
Windows обнаружила ST-LINK V2 (0483:3748), WSL lsusb показал только корневые концентраторы. В Windows PowerShell:
```powershell
STM32_Programmer_CLI -c port=SWD mode=HOTPLUG freq=100 -r32 0xE0042000 4
```
CubeProgrammer 2.23.0, ST-LINK V2J48S0, 2.90 В. На 4000 кГц цель не идентифицировалась. При 100 кГц прочитано 0x10036419, Device ID 0x419, Rev Y, Cortex-M4, Flash 2 МиБ. TC-02 пройден. Идентификатор общий для семейства F42x/F43x. Ревизию PCB подтвердить по маркировке. Использовалось только чтение.

## Первая аппаратная проба
После согласования остановки текущей программы выбрать доступный GDB-сервер с SWD через Windows, использовать ELF именно из проверенной сборки. Остановить ядро в привилегированном Thread mode, загрузить сегменты в SRAM, выставить MSP, выбрать MSP как активный стек, выставить Thumb PC по векторам, обнулить probe_result и установить аппаратную точку останова на probe_done. Продолжить исполнение и считать слово из probe_result. Критерий TC-03 — 0x429 и остановка на probe_done. Для повторных прогонов оформить сценарий stm32-gdbtest. По окончании перезапустить штатную прошивку. Для TC-04 потребуется отдельный Linux-образ и протокол консоли.

### Фактический результат TC-03, 04.11.2026
Проверена сборка из 4039d48. OpenOCD 0.12.0 через ST-LINK V2J48S0, SWD 100 кГц. На остановленном ядре дважды прочитано окно 0x20000000–0x20000fff. После сверки снимков загружены 32 байта кода и векторов, слово по 0x20000020 обнулено и прочитано обратно. Ядро было в обработчике SysTick и сохранило этот режим при запуске пробы. Аппаратный компаратор DWT остановил исполнение на probe_done (PC=0x20000016), значение probe_result равно 0x429. Оба критерия TC-03 выполнены.

После восстановления всё окно повторно считано и побайтно сверено. SHA-256 исходного, контрольного и восстановленного снимков — fa594f28c7e262e027e427151d58c45e1278672e969a2c00892ee8682d37434a. Изменённые регистры программы и настройки DWT возвращены, состояние ядра после продолжения — running. Операции программирования Flash и сброс не выполнялись.

### Частота SWD для Windows OpenOCD, 04.11.2026
Для чтения регистров на MB1075 B-01 проверена настройка `adapter speed 1800` (кГц, до init). В OpenOCD 0.12.0 на 950 и 1800 кГц успешны все три независимых подключения и 300 чтений DBGMCU_IDCODE на каждой частоте. На 4000 кГц все три подключения завершились ошибкой до серии чтений. Ядро не останавливали. Исполнение TC-03 и восстановление SRAM проверены отдельно на 100 кГц.

### Внешняя SDRAM на MB1075 B-01, 04.11.2026
Инициализатор FMC из внутренней SRAM завершился с r0=0. При HCLK 16 МГц, SDCLK 8 МГц, CAS 3 и COUNT=105 (64 мс / 4096 строк) прошли две серии записи и чтения в 24 полусловах. Адреса — база 0xD0000000, смещения-степени двойки от 2 до 0x400000 и последнее полуслово 0xD07FFFFE. Перед чтением каждого шаблона прошли 250 мс. Вся ёмкость сплошным проходом не испытывалась. После теста сверены значения 24 ячеек со снимком после инициализации, а также все 4096 байт внутренней SRAM со снимком до запуска. После SYSRESETREQ отдельное подключение подтвердило running и исходные регистры RCC/GPIO. Flash не программировалась.
